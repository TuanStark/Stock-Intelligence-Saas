# UI Blueprint — Stock Intelligence SaaS

**Version:** v1.0  
**Perspective:** Senior Software Engineer / Product UI Architect (10+ years)  
**Goal:** Define a production-grade, decision-first UI system for Stock Intelligence SaaS, including visual hierarchy, reusable component architecture, layout patterns, and interaction rules that support fast decision-making.

---

# 1. UI Philosophy

This product is not a decorative finance dashboard.

It is a **decision interface**.

The UI must not optimize for:

- visual density
- flashy charts
- decorative widgets
- “Bloomberg clone” aesthetics

The UI must optimize for:

- attention priority
- decision speed
- clarity
- signal emphasis
- reduced cognitive load

UI exists to answer:

1. What matters?
2. Why does it matter?
3. What should I do?
4. What supports that decision?

---

# 2. Visual System

## 2.1 Core Visual Principles

1. **Signal First**  
   Important signals must visually dominate.

2. **Clarity Over Density**  
   Show less, emphasize better.

3. **Hierarchy Before Decoration**  
   Visual weight must reflect decision value.

4. **Contrast Equals Priority**  
   More contrast = more important.

5. **Motion Must Teach**  
   Animation only supports understanding.

---

## 2.2 Visual Hierarchy Model

All screens follow this hierarchy:

### Level 1 — Decision

Highest visual weight  
Used for:

- signal strength
- stock score
- action-needed alerts
- market opportunity

### Level 2 — Explanation

Used for:

- signal reasoning
- AI summary
- thesis
- context

### Level 3 — Supporting Data

Used for:

- chart
- indicators
- metrics
- volume
- financials

### Level 4 — Utility

Used for:

- filters
- settings
- export
- metadata

### Rule

Visual emphasis must always follow decision hierarchy.

---

## 2.3 Color System

### Semantic Colors

- **Positive** → bullish / gain / healthy
- **Negative** → bearish / loss / risk
- **Warning** → caution / watch
- **Neutral** → informational
- **Accent** → interactive / actionable

### Rule

Color is semantic, not decorative.

Never use color for decoration only.

---

## 2.4 Typography System

### Typography Hierarchy

- **Headline** → screen decision context
- **Section Title** → decision block
- **Signal Value** → key metric emphasis
- **Body** → explanation
- **Meta** → support info

### Rule

Typography should emphasize decisions, not labels.

---

## 2.5 Spacing System

Spacing must create cognitive grouping.

Use spacing to separate:

- decisions
- explanations
- support layers

Rule:
More important blocks get more breathing room.

---

# 3. Component System

## 3.1 Component Philosophy

Components are not UI fragments.

Components are **decision primitives**.

Every component must do one of four jobs:

1. Surface signal
2. Explain signal
3. Trigger action
4. Support context

---

## 3.2 Core Component Types

### 1. Signal Components

Used for:

- stock score
- signal badge
- momentum tag
- opportunity marker

Purpose:
Surface importance instantly.

---

### 2. Explanation Components

Used for:

- thesis card
- AI summary card
- signal explanation block
- insight card

Purpose:
Reduce uncertainty.

---

### 3. Action Components

Used for:

- add to watchlist
- set alert
- add to portfolio
- upgrade CTA

Purpose:
Drive next action.

---

### 4. Data Components

Used for:

- chart
- metrics table
- fundamentals
- candles
- volume

Purpose:
Support validation.

---

### 5. Context Components

Used for:

- news card
- sector context
- macro pulse
- related signals

Purpose:
Explain “why now”.

---

### 6. Utility Components

Used for:

- filters
- sort
- date range
- export
- preferences

Purpose:
Support workflow.

---

# 4. Layout System

## 4.1 Layout Philosophy

Layout is not for symmetry.

Layout is for attention routing.

The screen must guide the eye in decision order.

---

## 4.2 Screen Layout Pattern

Every primary screen follows:

```text
Top: What matters now
Middle: Why it matters
Lower: What to do
Bottom: Supporting detail
```
